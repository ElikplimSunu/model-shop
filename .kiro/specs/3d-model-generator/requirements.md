# Requirements Document

## Introduction

This document specifies the requirements for a 3D model generation feature that integrates with NVIDIA's Trellis API. The feature allows users to generate 3D models from either image uploads or text descriptions, then view and interact with the generated models directly within a Next.js web application.

## Glossary

- **Model_Generator**: The system component responsible for generating 3D models via the NVIDIA Trellis API
- **Input_Handler**: The system component that processes user input (images or text)
- **Model_Viewer**: The system component that renders and enables interaction with 3D models
- **API_Client**: The system component that communicates with the NVIDIA Trellis API
- **User**: A person interacting with the web application
- **3D_Model**: A three-dimensional digital representation generated by the Trellis API
- **Base64_Image**: An image encoded in base64 format for API transmission
- **Generation_Request**: A request to create a 3D model containing input data and configuration parameters

## Requirements

### Requirement 1: Input Selection

**User Story:** As a User, I want to choose between image upload or text input, so that I can generate 3D models from different types of source material

#### Acceptance Criteria

1. THE Input_Handler SHALL provide an interface for selecting between image upload and text input modes
2. WHEN the User selects image upload mode, THE Input_Handler SHALL display an image upload interface
3. WHEN the User selects text input mode, THE Input_Handler SHALL display a text input interface
4. THE Input_Handler SHALL allow the User to switch between input modes before submission

### Requirement 2: Image Upload Processing

**User Story:** As a User, I want to upload an image file, so that I can generate a 3D model based on that image

#### Acceptance Criteria

1. WHEN the User uploads an image file, THE Input_Handler SHALL accept common image formats (JPEG, PNG, WebP)
2. WHEN an image is uploaded, THE Input_Handler SHALL encode the image data to base64 format
3. WHEN an image exceeds reasonable size limits, THE Input_Handler SHALL display an error message to the User
4. THE Input_Handler SHALL display a preview of the uploaded image before submission
5. WHEN the image encoding fails, THE Input_Handler SHALL display a descriptive error message

### Requirement 3: Text Input Processing

**User Story:** As a User, I want to enter text descriptions, so that I can generate 3D models from textual prompts

#### Acceptance Criteria

1. THE Input_Handler SHALL accept text input up to 500 characters
2. WHEN text input is empty, THE Input_Handler SHALL prevent submission and display a validation message
3. THE Input_Handler SHALL display the current character count to the User
4. WHEN text input exceeds the character limit, THE Input_Handler SHALL prevent additional character entry

### Requirement 4: API Authentication

**User Story:** As a Developer, I want secure API authentication, so that the application can communicate with the NVIDIA Trellis API

#### Acceptance Criteria

1. THE API_Client SHALL authenticate requests using a Bearer token from the NVIDIA_API_KEY environment variable
2. WHEN the NVIDIA_API_KEY is not configured, THE API_Client SHALL return a configuration error
3. THE API_Client SHALL include the Bearer token in the Authorization header of all API requests
4. THE API_Client SHALL not expose the API key in client-side code

### Requirement 5: 3D Model Generation Request

**User Story:** As a User, I want to submit my input for 3D model generation, so that I can receive a generated 3D model

#### Acceptance Criteria

1. WHEN the User submits valid input, THE Model_Generator SHALL create a Generation_Request with the following parameters: slat_cfg_scale of 3, ss_cfg_scale of 7.5, slat_sampling_steps of 25, ss_sampling_steps of 25, and seed of 0
2. WHEN image input is provided, THE Model_Generator SHALL include the Base64_Image in the Generation_Request
3. WHEN text input is provided, THE Model_Generator SHALL include the text in the Generation_Request
4. THE API_Client SHALL send the Generation_Request to https://ai.api.nvidia.com/v1/genai/microsoft/trellis
5. WHEN the API request is in progress, THE Model_Generator SHALL display a loading indicator to the User

### Requirement 6: API Response Handling

**User Story:** As a User, I want to receive feedback on my generation request, so that I know whether the 3D model was successfully created

#### Acceptance Criteria

1. WHEN the API returns a successful response, THE Model_Generator SHALL extract the 3D_Model data from the response
2. WHEN the API returns an error response, THE Model_Generator SHALL display a descriptive error message to the User
3. WHEN the API request times out, THE Model_Generator SHALL display a timeout error message
4. WHEN a network error occurs, THE Model_Generator SHALL display a network error message
5. THE Model_Generator SHALL log API errors for debugging purposes

### Requirement 7: 3D Model Display

**User Story:** As a User, I want to view the generated 3D model, so that I can see the result of my generation request

#### Acceptance Criteria

1. WHEN a 3D_Model is successfully generated, THE Model_Viewer SHALL render the 3D_Model in the application interface
2. THE Model_Viewer SHALL display the 3D_Model with appropriate lighting and perspective
3. THE Model_Viewer SHALL fit the 3D_Model within the viewport boundaries
4. WHEN the 3D_Model fails to load, THE Model_Viewer SHALL display an error message

### Requirement 8: 3D Model Interaction

**User Story:** As a User, I want to interact with the generated 3D model, so that I can examine it from different angles

#### Acceptance Criteria

1. WHEN the User drags on the 3D_Model, THE Model_Viewer SHALL rotate the model according to the drag direction
2. WHEN the User uses scroll or pinch gestures, THE Model_Viewer SHALL zoom the 3D_Model in or out
3. THE Model_Viewer SHALL support panning the 3D_Model view
4. THE Model_Viewer SHALL provide controls to reset the view to the default position
5. THE Model_Viewer SHALL maintain smooth frame rates during interaction (minimum 30 FPS)

### Requirement 9: Generation History

**User Story:** As a User, I want to see my previous generation requests, so that I can revisit earlier 3D models

#### Acceptance Criteria

1. THE Model_Generator SHALL store generation history in browser local storage
2. WHEN a 3D_Model is successfully generated, THE Model_Generator SHALL add it to the generation history
3. THE Model_Generator SHALL display a list of previous generations with thumbnails
4. WHEN the User selects a previous generation, THE Model_Viewer SHALL display that 3D_Model
5. THE Model_Generator SHALL limit history to the 10 most recent generations

### Requirement 10: Error Recovery

**User Story:** As a User, I want to retry failed generation requests, so that I can recover from temporary errors

#### Acceptance Criteria

1. WHEN a generation request fails, THE Model_Generator SHALL display a retry button
2. WHEN the User clicks the retry button, THE Model_Generator SHALL resubmit the previous Generation_Request
3. THE Model_Generator SHALL preserve the original input data for retry attempts
4. THE Model_Generator SHALL limit retry attempts to 3 per Generation_Request
5. WHEN retry attempts are exhausted, THE Model_Generator SHALL display a message suggesting the User try different input
